# Reproducible ContextLens experiments

The Visual-to-Code work is an isolated browser/source-mapping experiment, separate from the native app. The [public research summary](../docs/research.md#visual-to-code-and-historical-evidence) explains its scope and limits; [reusable code and offline tests](../Experiments/visual-to-code/README.md) remain public. The detailed historical report and its trace dataset are local-only and deliberately not linked as public files. Profiling commands require a newly supplied dataset; they are not reproducible historical results from a clean checkout. Mapping/payload checks do not establish token savings or general source-localization benefits.

Historical studies did not establish consistent agent token savings. Human preparation time remains unmeasured. Private execution traces, account observations and historical authorization are not distributed. See [public research guidance](../docs/research.md). Reproduction requires fresh authorization before any model invocation.

## Install and verify

```sh
scripts/build-app.sh
npm --prefix Benchmarks install --ignore-scripts
npx --prefix Benchmarks playwright install chromium
python3 -m venv .venv
.venv/bin/pip install -r Benchmarks/requirements.txt
python3 -m unittest discover -s Benchmarks/tests -v
node Benchmarks/runners/verify-fixtures.mjs
node Benchmarks/runners/capture-fixtures.mjs /tmp/contextlens-browser-evidence
.venv/bin/python Benchmarks/runners/report.py
```

Run commands from the repository root. Playwright is pinned to 1.62.1; keep its browser revision consistent across trials. `npm install` was network-blocked in the initial sandbox. For this implementation's browser checks, the existing Playwright 1.62.1 installation and Chrome were supplied using `PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs` and `CHROMIUM_EXECUTABLE=/absolute/path/to/Chrome`. Both overrides are optional. `package-lock.json` was subsequently generated by a permitted local installation; use `npm --prefix Benchmarks ci --ignore-scripts` for exact dependency resolution. Record the exact actual browser version when comparing results.

The Python plotting libraries are optional development dependencies; app build and Python core tests do not require them. They can also be installed under `.build/benchmark-python` and used with `PYTHONPATH="$PWD/.build/benchmark-python"`. Matplotlib uses the headless Agg backend, and caches are local to `.build`.

`verify-fixtures.mjs` independently checks ten broken task properties (must fail), ten known-good controls (must pass), and twelve baseline-passing regression guards. The known-good implementations and evaluator are outside `tasks/` and never copied to agent workspaces. This evaluator is independent of the coding agent, but structural/focus/color checks are proxies; visual polish still needs independent human review.

`capture-fixtures.mjs` captures **only local fixture pages** in headless Chrome, records actual sample timestamps, replays PNGs through the production selector and exports the sessions. It creates an auto-only package from the same selected states and measures four initial filesystem delivery strategies. Its generated annotations use the task catalog's explicit desired result. These are scripted demonstration packages, not measurements of human reporting effort. Never put their timings into the Manual/Auto-only/ContextLens human comparison.

## Tasks and baselines

`task-catalog.json` describes the same ten task scopes for every workflow. `tasks/` holds a deliberately broken, dependency-free application: modal alignment, card spacing, sidebar overlap, dropdown interaction, mobile overflow, active tab styling, keyboard focus, validation feedback, modal scrolling and counter updates. Each route is `?task=01` through `?task=10`.

The live harness creates a fresh OS-temporary project from the same fixture source for every trial. It initializes and records a reproducible Git baseline commit before adding evidence, as well as a SHA-256 content digest. No conversational session or prior code diff is reused. Result projects, patches, traces, exact invocations and evaluation artifacts are retained under `runs/`. Temporary workspaces are removed after successful recording. Source copies keep acceptance tests/solutions outside the visible project; this is experimental separation, not an OS-level guarantee against an adversarial agent reading unrelated host paths.

- **Manual:** an operator takes/crops screenshots, writes a report in `task.md`, and puts evidence in a new folder. Measure the complete preparation. Use the catalog's task scope; do not disclose hidden tests or source fixes.
- **Auto-only:** the operator uses the same recording events and ordered screenshots with simple observed captions, and writes the same requested task in `task.md`. No region-sidecar annotations, targeted crops, or structured progressive report. Use the same captured states as ContextLens where possible to isolate annotation/compiler value.
- **ContextLens:** the operator records, selects frames, annotates the target, exports the package and writes/copies the minimal instruction into `task.md`. All review and annotation time counts as preparation. Do not replace observed effort with scripted fixture capture times.

Keep the starting commit, source, model, reasoning effort, permissions, tools, dependency/browser versions, timeout, viewport and resource conditions fixed within each paired experiment. Use the default seeded randomized plan or a counterbalanced condition schedule. Reset the app and browser state and use fresh conversations between trials. Avoid the same operator repeatedly solving a task in one order without counterbalancing; learning may dominate preparation time. Record operator identity/anonymized experience and interruptions in additional ledger fields. Repeat trials where budget permits. Treat small samples as exploratory.

## Run actual comparisons

Generate a no-cost schedule; this never starts an agent:

```sh
python3 Benchmarks/runners/harness.py --tasks 01 04 10 --trials 3 --seed 1729 > /tmp/contextlens-plan.json
```

For **each entry in that schedule**, prepare and hand off immediately. First time the actual workflow:

```sh
python3 Benchmarks/runners/time_preparation.py 01/manual/1 /absolute/path/to/prepared-manual --ledger /tmp/contextlens-preparations.json
```

The interactive timer records observed timezone-aware T0/T1. `task.md` must exist when the report is complete. It does not invent active human seconds. The ledger's `operator_observed` field confirms the operator timing; capture interruptions and active effort independently if needed. Preparing all packages in advance creates biased queue time and is rejected when T1 is more than 300 seconds old. Run one condition immediately after preparation, following the recorded schedule:

```sh
python3 Benchmarks/runners/harness.py --agent codex --model YOUR_CODEX_MODEL --effort high --tasks 01 --conditions manual --trials 1 --preparations /tmp/contextlens-preparations.json --output Benchmarks/runs --live --allow-paid
```

Equivalent Claude Code trial:

```sh
python3 Benchmarks/runners/harness.py --agent claude --model YOUR_CLAUDE_MODEL --effort high --budget-usd 1 --tasks 01 --conditions manual --trials 1 --preparations /tmp/contextlens-preparations.json --output Benchmarks/runs --live --allow-paid
```

Replace the condition with `auto-only` or `contextlens`, and record that exact key in the ledger. For later repeated trial IDs, use `--trial-start N`. Keep model and effort identical **within one provider's comparison**. Model names are deliberately supplied by the operator rather than guessed. `--live --allow-paid` is an explicit spending gate; it does not grant permission outside your existing authorization. No live trial was run during implementation. Claude has a per-run provider budget cap; Codex exposes no corresponding hard USD cap here, so its limit is the 600-second default timeout and whatever account limits you configure separately. Never describe `--budget-usd` as a Codex spending cap.

The adapter uses argv arrays and stdin rather than shell interpolation, disk-backed traces and process-group timeouts. Codex runs with `workspace-write`, ephemeral sessions and ignored user config. Claude uses safe mode, no MCP/config discovery, `acceptEdits` with unattended permission prompts denied, a limited tool list and bounded allowed shell patterns. It never uses bypass flags. These are reproducible defaults, not a security container or perfect cross-agent equivalence. Make same-agent comparisons primary and disclose provider permission/tool differences.

The harness records the first attempt, target acceptance, twelve shared regression checks, provider exit/errors, patch and complete output. It does not automatically run corrective paid iterations. Failed first attempts remain failures/censored time-to-success. To study corrections, preserve the failing project, obtain operator intervention consistently, and append independently timed corrective traces/usage to the experiment dataset before comparing time-to-success; the current first-attempt report must not claim those corrections were measured.

## Telemetry semantics

Observed CLIs: Codex **0.163.0**, Claude Code **2.1.303**. CLI help and the official [Codex non-interactive guide](https://learn.chatgpt.com/docs/non-interactive-mode) and [Claude programmatic guide](https://code.claude.com/docs/en/headless) were reviewed. `--version` is stored for every live invocation.

Codex JSONL: sum **only** root `turn.completed.usage` per turn. `input_tokens` includes cache hits; uncached = input − cached input, when both fields exist. Output includes provider-accounted reasoning; if a separate reasoning field appears, retain it without adding it twice. Ignore cumulative token_count and nested item usage. The Codex turns count is completed CLI conversation turns, while Claude num_turns uses that provider's definition; do not compare these counts across providers as equal units. Provider-reported totals are stored separately; missing reasoning, costs and counts remain null.

Claude JSON result: the root `usage` aggregates its turns; do not add `modelUsage` again. Total input = uncached `input_tokens` + `cache_read_input_tokens` + `cache_creation_input_tokens`, only when all are exposed. Output and root `total_cost_usd`, `duration_ms`, `num_turns` and model identifiers are recorded when available. A missing cache field stays unavailable, not zero. Preserve full provider traces for version-specific review.

The harness does not estimate billing costs from token totals or image file sizes. Provider-reported cost is preferred; no hard-coded price table is supplied. Tokenizers and cache semantics differ by model family. Cross-agent totals are not directly equivalent.

## Time, correctness and reports

T0: operator starts preparation. T1: report is ready and handed off immediately. T2: CLI invocation. T3: initial CLI completes. T4: independent acceptance/regression checks pass. Record T1→T2 queue delay separately. Preparation = T1−T0; execution = T3−T2; end-to-end = T4−T0. Failed attempts retain elapsed time and null T4/end-to-end. Evaluation time is included in time-to-accepted-result. Browser CPU time is not human preparation. No active human effort value is synthesized.

```sh
.venv/bin/python Benchmarks/runners/report.py --runs Benchmarks/runs --output Benchmarks/reports
```

`results.json` contains individual attempts, within-agent/model/effort groups, medians/IQR, success rates, failure counts, all-observed paired differences, successful-pair reductions and end-to-end speedup. Bootstrap median-difference intervals are added only at ≥10 successful pairs. Failures remain in total token/cost summaries; success-only timing is labeled. Duplicate live keys are rejected to prevent accidental double-counting. Reports never load synthetic parser fixtures as live results.

Charts: grouped token consumption, completion time, preparation time and success rate; scatter at ≥6 complete live observations. With no live trials the four charts explicitly display “Live benchmark pending” without numerical bars. A separate payload chart uses real exported filesystem measurements and labels them as bytes, not tokens. `fixture-validation.json` is evaluator validation, not agent accuracy.

For the strategy experiment use `--strategies` for a seeded schedule of `all-frames`, `deduplicated`, `annotated`, `manifest-first`, then supply independently prepared evidence folders/timings for those keys and run them one at a time with `--conditions`. `task.md` must prescribe which initial evidence to inspect in each strategy. Keep task scope and correctness tests equal. Initial payload measurements alone cannot establish the winning strategy.

## Average savings and application workloads

The report includes **arithmetic means** as well as medians/IQR. Paired savings use Manual minus ContextLens: positive is a saving, negative is an increase. `all_observed_savings_manual_minus_contextlens` retains failed attempts with available token usage; `successful_pair_savings_manual_minus_contextlens` conditions on both passing. Read those beside failure counts, paired-attempt counts and missing-measurement counts. Missing or malformed usage is never zero. Successful-pair mean bootstrap intervals appear only at ten pairs; repeated task/operator observations are exploratory, not independent population evidence.

Groups also separate CLI version, source digest, timeout, Node version, command and platform. Averages across different settings are not pooled. The current study remains **pending** until real provider traces and operator-timed preparation exist. Historical local schedules under `reports/rigorous-testing/` are not distributed; generate a fresh no-cost plan with the harness command above, then obtain explicit authorization before any model invocation.

```sh
# Optional before/after native memory comparison with a preserved baseline bundle:

```

Native commands require a genuine disposable interactive macOS environment; the flag only acknowledges that setup and never grants permission or creates isolation. Do not run them on the owner's working desktop. These generated screenshot/animation workloads report machine/source identity, exact commands, peak RSS, timing distributions and raw outcomes in `reports/rigorous-testing/`. WindowServer and `/usr/bin/time -l` need ordinary macOS process access; a restricted execution sandbox may block them. The soak runs ten minutes at each sensitivity, sequentially, against its own generated window only. Its CPU includes fixture animation and its scroll hold is scripted; it does not substitute for a real application's interactive release test. Actual keystroke-to-display latency and zoom/pan FPS remain separate measurements.
