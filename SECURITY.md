# Security and privacy

ContextLens captures one explicitly selected window and writes local files. It does not upload evidence or run agents. See [privacy and storage](docs/privacy.md) for permissions, redaction limits and retained originals. Review screenshots, titles, labels and instructions before sharing; current rectangle/highlight tools do not create new redactions.

Do not post secrets, personal captures or raw agent transcripts to public issues. For a suspected vulnerability, use the repository's private security reporting channel when enabled; if unavailable, open a minimal issue requesting a private contact without sensitive details. Never include credentials or signing keys.

Contributors must run the [publication checks](docs/publication-security.md) and review staged content. `scripts/audit-public-files.py --staged` reports targeted patterns without printing matched values; it does not replace manual review. Keep account receipts, private traces and signing material out of Git history.

The [publication security checks](docs/publication-security.md) now cover index blobs, all reachable history, exact synthetic-fixture approvals, metadata and an independent local Gitleaks scan. CI runs these with read-only permissions and no source-upload service. Pixel review, deleted server refs/forks and deliberate obfuscation remain outside an automated clean-scan guarantee. A genuine exposure stops publication; rotate/revoke affected credentials and obtain explicit approval before rewriting history or deleting releases.

Trusted stable binaries must pass Developer ID signing, Apple notarization, stapling and Gatekeeper verification. Those production gates remain mandatory. The separate [unnotarized preview channel](docs/preview-releases.md) publishes explicitly labeled GitHub prereleases with ad-hoc signatures, source provenance and verified SHA-256 checksums. These signatures are not public developer trust, and Apple has not verified the previews. Authorize a preview only after checking its origin and intact download, using Apple's user-controlled Open Anyway process if available. No release script disables Gatekeeper, removes quarantine or overwrites published tags/assets. The separately gated [official unnotarized channel](docs/official-release-preparation.md) also uses ad-hoc signatures and requires exact-byte native engineering and human security acceptance. It does not relax the Developer ID channel. Five human security cases remain pending; no stable release or cask is published.
